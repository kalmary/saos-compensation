## Summary

get_data.py is the only implementation module at the dataset package root, alongside __init__.py. Pipeline orchestration and checkpoints live in acquisition/; record exports and atomic file writes live in storage/. Extraction and embeddings retain their separate packages. basal_filtering.py now coordinates extraction in 79 lines; model/ groups configuration, prompts and decision caching; source/ groups text normalization and passage batching; targets/ groups monetary evidence and target resolution. Feature extraction and quality checks remain beside the coordinator. Source, tests and notebook callers use the new imports. CLI options, extraction settings, record schemas and checkpoint compatibility remain unchanged. Offline validation passes 324 tests with one missing-fixture replay skipped.

Target selection now uses embedding similarity to configs/dataset/target_pattern.yaml, configured by embedding.yaml. The pinned Polish-capable multilingual MiniLM encoder supports explicit CPU/MPS/CUDA devices, batches all token windows, and caches pattern embeddings once per configuration. Before encoding, candidate_keywords uses judgment/request/shared word-prefix groups plus a numeric PLN amount with currency in the same sentence; role-specific hits restrict class eligibility and shared stems are a fallback; irrelevant sentences never reach the encoder, and no candidates means no model loading. Prior-payment, procedural-cost, mixed request/outcome and other-payment patterns now compete with target roles; exclusion winners are diagnostic only. Each candidate is assigned only its highest-scoring eligible class, strictly above minimum_cosine_similarity=0.7; several qualifying classes still produce one winner. Exact ties prefer exclusions, then pattern order. A judgment match is required and request is optional. Embedding weights are in the separate ignored embedding_weights/ folder with .gitkeep retained.

The sole public target is total, exported with valid only in award.json; target_fields: [total] maps to the internal Basal suma adapter. Basal resolves principal roles without compensation subtype classification after sentence selection, using all current operative-ruling clauses when the boundary is unambiguous. Ambiguous multiple principal figures in one sentence are rejected to avoid double counting. Multiple beneficiaries are supported with one case-level aggregate, explicit per-person multiplication, recipient deduplication and the configured injured_party_count feature. Optional request amounts remain outside predictor features. prior_payment is now an explicitly allowed numeric feature: Basal resolves confirmed earlier principal from the embedding-selected prior-payment sentence, rounds it half up to integer PLN and defaults to zero without confirmation. It is stored only in record.json and never added to award.json or the awarded total. Text-feature leakage checks remain unchanged. Unknown counts/amounts remain missing. Requested amounts and monetary decisions are internal/debug-only; award.json includes only total and valid; record.json contains only selected features. Debug additionally saves only source.txt and model_calls.json, including embedding-match diagnostics, and retains other failed completed attempts as invalid only when text-feature coverage passes.

The current extractor is version 19; older checkpoints require a fresh output path. YAML/CLI acquisition overrides, cumulative size limits and per-judgment interruption recovery remain. Both model caches must be outside a size-limited output directory. The six text features are now event_description, harm_description, harm_duration, practical_impact, claimant_context and remedial_actions. Short Polish extraction and positive field-relevance questions cover cause, harm/loss, time, disrupted activities/plans, pre-event context and remediation without assuming injury. Console diagnostics use existing answers to distinguish absent descriptions, currency, factuality confidence, leakage and field relevance. Target errors are preserved before coverage, skipped feature extraction is explicit, and unexecuted final award verification reports its earlier cause and available classification score. Source-grounded feature extraction still starts from factual findings, checks candidate field relevance/leakage and never revisits other passages for missing fields. Cases require source-backed descriptions for strictly more than half of configured text features (four of the current six); insufficient coverage discards the case even under debug, excluding metadata and prior_payment from the count. The protected model_input.yaml was not changed.

The embedding extra is declared in pyproject.toml and uv.lock and was synced separately with pytorch-macos before execution. Validation: 324 offline tests pass, one missing-fixture replay is skipped. The synthetic MPS two-recipient example resolves 20,000 each to an aggregate 40,000. CPU embedding inference also succeeds. CUDA was not checked on hardware.

Real saved-text matching took approximately 0.2–0.5 seconds per case after loading, but the three inspected judgments contained incorrect or mixed-role matches even above 0.7. This is a known quality limitation, not a calibrated confidence estimate. Details: tmp/embedding_target_review.md. A live run incorrectly accepted 215,600 PLN requested compensation for 255711, despite a ruling for 65,600 PLN compensation plus 323.29 PLN other damages. Basal's final validation did not prevent this error. The grouped matcher separates the request from a 65,600 PLN reasoning sentence on that saved text. Competing exclusion groups now remove the previously selected fees/prior payment in 256099 and 328131; both saved-text cases currently have no judgment match, despite containing real awards. The five direct role/context checks pass with the real cached CPU encoder. Independent labeled evaluation and operative-ruling safeguards remain outstanding. The completed keyword-filter stage was committed and pushed after explicit authorization; the exclusion stage is validated separately.

Live persistence checks passed interruption/resume, debug file layout, pending-state cleanup and a cumulative size-limit refusal. Court-seat matching resolves 212/374 courts; city-only candidates would resolve 354/374 but remain unverified. The two current distinct debug cases have six populated text fields with no exact within-case duplication, yet field-relevance and beneficiary-attribution errors remain. Full findings and proposals: tmp/dataset_audit_20261031_183052/review.md.

The project continues to use official date-bounded SAOS dump ingestion. The documented API has no structured victim-count or awarded-compensation fields; thematic keywords and court/division metadata can help filtering but cannot establish the target. PostgreSQL/pgvector ingestion, training, evaluation and inference pipelines remain future work.
