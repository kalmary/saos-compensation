## Summary

The dataset source pipeline reads full judgments from `/api/dump/judgments`, applies its date range, filters compensation judgments locally, and joins court/division metadata from `/api/dump/commonCourts`. A shared requests Session makes one timed request per resource without manual retries. Live dump schema inspection confirmed that `info` is null and judgment items contain only a division ID; pagination uses `next` rather than result counts.

`configs/dataset/api.yaml` provides defaults for age, page limit, download path, debug, download-only mode and timeout. Matching CLI arguments override only explicitly supplied values, including negative boolean flags. The normal output is `<download_path>/<SAOS_ID>/record.json` with configured features, targets, their derived total and review statuses. Download-only mode writes source.json instead. Debug controls all persistent source/evidence/intermediate/model-request exports; ordinary extraction saves only primary records. Previous outputs are preserved.

The selected `wielkość miejscowości` feature is supported using official GUGiK BDOT10k population classes and Morfeusz court-seat matching. Ambiguous matches remain missing. The snapshot has no population measurement year and is not verified historical demographics. Diagnostic mode preserves source provenance, exact model calls, scores, offsets, rejected candidates and original source passages; these explain extraction decisions, not future regressor predictions.

Validation: 170 tests pass, including ten saved Basal development-case replays, configuration/CLI precedence, debug-only persistence, HTTP timeout/no-retry behavior, dump pagination, output records and population enrichment. Source configuration loads successfully. Independent target/feature quality and leakage evaluation remain outstanding; automatic model confirmation is not a reviewed training label. PostgreSQL/pgvector storage, dataset splits, vectorization and regression training remain outside this acquisition/extraction task.
