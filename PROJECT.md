# SAOS Compensation

## Objective

Build a reproducible regression pipeline that estimates the compensation awarded in Polish court judgments available through SAOS. This is a study project for a data science course.

## Delivery plan

### 1. Acquire judgments and produce reviewable records

1. Read full judgments from the official SAOS `/api/dump/judgments` endpoint with a bounded judgment-date range. Resume dump pagination from checkpoint.json until the configured page limit or final page. The dump has no documented text/court filter, so select common-court compensation judgments locally. Join court/division metadata from `/api/dump/commonCourts`.
2. Use one shared HTTP session, an explicit timeout and one attempt per request. Report HTTP, pagination and validation failures; do not silently retry or discard malformed records. Refetch the pending page on resume, verify its IDs against the checkpoint and deduplicate by stable SAOS ID. Skip already committed records from the same dataset.
3. Treat `configs/dataset/acquisition/api.yaml` as the defaults for acquisition: age range, page limit, total output size (max_gib), download path, debug and timeout. Expose matching CLI arguments; only explicitly supplied arguments override YAML. `--no-debug` must override a true YAML value.
4. Locate target sentences by embedding similarity to configs/dataset/acquisition/targets.yaml. The judgment class is mandatory; request is optional. Encode each pattern once, first retain only sentences containing a numeric PLN amount (including currency) and a configured candidate_keywords word stem, then compare candidates only with eligible classes: judgment/request stems restrict target eligibility, shared stems enable both only when no target-role stem occurs, and stems from both roles leave the choice to similarity. Additional prior_payment, procedural_costs, mixed and other_payments keyword/pattern groups compete with those roles; an exclusion winner cannot supply either target role. Keep the best match per exclusion group in debug diagnostics. Require a score strictly greater than minimum_cosine_similarity (default 0.7), and retain the highest score per class. A sentence belongs only to its highest-scoring eligible class; multiple above-threshold groups still produce only the highest-scoring winner. Exact ties prefer an exclusion class, then the first class in pattern order. Similarity is not a calibrated probability. After a judgment match, parse the numeric PLN value directly from that exact sentence using decimal arithmetic. Do not scan other ruling clauses or ask Basal to classify or verify target amounts. Require exactly one numeric PLN occurrence in the selected sentence; missing or multiple occurrences leave the target unresolved. Multiple beneficiaries are supported within that sentence: multiply an explicit per-person amount only when its recipient group can be counted from source text; preserve unknown counts and reject unresolved per-person totals. Separate awards in other sentences are not aggregated. injured_party_count is derived from explicit recipients in the selected sentence and defaults to integer 1 when the count is unavailable. This predictor default is applied during record enrichment only; it never establishes an unknown count for per-person target multiplication. prior_payment is an explicitly allowed numeric predictor, resolved separately from the winning prior_payment sentence by source-grounded Basal extraction. It stores an integer PLN amount rounded half up to the nearest złoty, or 0 without a confirmed amount. Select an explicit prior-payment total when available; do not sum repeated mentions or ambiguous separate payments. This feature never enters award.json or the awarded total, and its passage stays excluded from text features. amount_minimum_probability applies only to the prior_payment predictor, not the regression target. All records require at least one accepted source-backed text description among cause, damage and limitations. No particular field or percentage is required; metadata does not count. Cases with no accepted text description are discarded even under debug. Among cases with accepted text evidence, normal records require a judgment match, a valid principal and safe features; debug retains other failed attempts with valid=false. award.json stores only total and valid; requested amounts, component evidence and monetary decisions remain internal/debug-only; record.json contains only features. Match sentences, scores and pattern evidence are debug-only in model_calls.json.

5. With debug enabled, add only model_calls.json and source.txt in the same judgment folder. Do not save analysis, raw payloads, reports, config copies or extra debug subdirectories. Retain operational checkpoint.json and temporary pending state for interruption recovery; remove pending state after acceptance or rejection. Rejected cases leave no basic or debug files; all retained attempts failing admission are debug records marked valid=false. Commit the four case files before removing temporary pending state. Summaries remain console-only. Previously created artifacts are preserved rather than deleted automatically.
6. Keep the device in `configs/dataset/acquisition/basal.yaml`: MPS for the current macOS experiment, with CPU/CUDA alternatives and device availability checked before downloads. Use the `pytorch-macos` dependency extra for local macOS work and `pytorch-cuda-linux` for NVIDIA GPU execution on Linux. Feature names are English while their model-facing descriptions and judgment text are Polish. basal.yaml selects the supported model, device and confidence thresholds. Model revisions and technical source/leakage instructions remain pinned in code; features.yaml is the single source of text questions and selected predictors. The same question is used for extraction and field-relevance review.
7. Derive judgment year from SAOS metadata, require evidence for procedural instance, and derive the population class of the locality where the court is located from the matched GUGiK locality and its LICZBAMIESZKANCOW field. Count awarded beneficiaries for injured_party_count, distinguishing individual amounts from a joint amount. Default the predictor to 1 when unavailable; unresolved per-person targets still remain missing. A current population snapshot does not establish population at judgment time.
8. Write `<download_path>/checkpoint.json` independently of debug. Pin the dataset ID, request dates, extraction configuration and GUGiK snapshot hash; store the next page/item and current page IDs. Commit the final record before advancing progress, and recognize an already saved record if interrupted between those writes. Resume automatically with the same command. Debug, timeout, max_gib and page limits may change; a different extraction configuration, age range or fresh dataset requires a new download path. Completed checkpoints perform no further acquisition. Persist completed model decisions, source and configuration in <SAOS_ID>/pending/ independently of debug so interruptions inside a judgment do not repeat completed inference. Retain pending state after interruption and remove it after a successful record commit or explicit rejection; its bytes count toward max_gib.
9. Enforce max_gib against all files already in the output directory, including prior executions and atomic temporary writes; zero disables the limit. Stop before a write exceeds the budget, leaving a resumable checkpoint. Keep model weights in the ignored basal_weights/ directory, with one Hugging Face models--<owner>--<model> subfolder per model. Missing weights download automatically when extraction starts; cached files are reused. Request only root-level weights, tokenizer, configuration and calibration files, with one file-download worker; Xet transport may separately parallelize transfer/reconstruction internally. Embedding model weights use the separate ignored embedding_weights/ folder with .gitkeep retained. Keep both model caches outside the size-limited output directory.
10. Keep normal output to record.json and award.json, adding only source.txt/model_calls.json when debug is enabled. Select the court factual-findings section using explicit headings, falling back to the reasoning body when no heading is available. Extract all selected text fields together in sentence-aligned batches of up to 6000 characters. Use three simple text features defined in features.yaml: cause asks what caused the harm; damage asks what harm the injured party suffered; limitations asks which activities were difficult or impossible. Questions stay short and general, without examples or enumerated harm types. These describe the cause, the harm/loss itself and unavailable activities respectively, without assuming bodily injury. Missing source information remains missing; semantic distinction does not imply that one multi-fact source sentence can never support two fields. Attribute facts to the injured party. Review only selected source candidates for factuality, currency exclusion, target leakage and relevance to each proposed field. Console diagnostics distinguish no extracted description from currency, non-factual text, low factual confidence, leakage and poor field relevance, reporting existing scores and thresholds without additional model questions. Preserve target rejection reasons before required-feature rejection, and explicitly report when feature extraction was skipped. Report unresolved targets using their selected-sentence parsing status; do not report Basal amount probabilities or final verification for embedding-derived targets. Share source reviews across fields and try lower-ranked candidates when needed. Do not run a second extraction pass outside the primary section. Unsupported fields remain not_available. Require a nonempty text_fields mapping in features.yaml and at least one accepted source-backed text description for every retained record, including debug records. No individual text field is mandatory; other features may remain missing. Leakage and relevance checks remain active for every populated text feature. The extractor version is saos-extraction-26; older checkpoints require a separate output path. Keep PostgreSQL/pgvector ingestion separate. Model comparisons use the same saved judgments without changing the active model selection.


The first milestone is complete when a bounded acquisition produces records with explicit accepted/rejected counts, source validation, deliberate missing-value handling and debug-controlled traceability. A complete run does not establish target accuracy or approval for training.

### 2. Define the learning dataset

1. Specify how the awarded amount in PLN is extracted and how multiple awards, claimants, currencies, interest, appeals, and rejected claims are treated.
2. Label a small representative sample manually and use it to measure extraction quality.
3. Define a stable feature schema, beginning with:
   - cause of harm,
   - region,
   - court type and level,
   - judgment date,
   - claimant and harm characteristics supported by the judgment.
4. Evaluate a single open-weight instruction model supporting Polish for extracting and standardizing text features into this schema. Use a fixed model version and prompt, controlled categories, missing-value rules, and source evidence; measure quality on the labeled sample before choosing a model.
5. Store extracted fields together with the extractor name and version.

Label extraction and feature extraction must be separate. Predictor text must exclude the award, requested amount, calculations derived from it, and passages that directly explain the selected award. Related judgments and appeals must remain in one data split.

The second milestone is complete when target extraction and the feature schema reach agreed quality on the labeled sample and pass leakage review.

### 3. Vectorize and train

`from src.dataset.embeddings import create_embeddings` exposes reusable encoding in src/dataset/embeddings/encoding.py. Call create_embeddings(texts, settings) with a nonempty list of nonblank strings and encoder settings (model, revision, device, batch_size, max_length); matcher-specific settings are optional and ignored by the encoder. It returns an N-by-D float32 PyTorch tensor on the selected device, preserving text and input order and pooling every token window. Encoding settings and input batches are validated before model loading. The last loaded encoder is cached by encoding settings only. The target matcher uses this function for patterns and candidates; monetary normalization remains in target_matching.py, so unrelated callers embed their original text. No model is loaded on import. This extraction of the encoder preserves vector values, configuration, output schema and checkpoint compatibility; it does not implement feature-vector persistence or regressor preprocessing.

`src/dataset/embeddings/cosine_similarity.py` compares existing embedding vectors or matrices using PyTorch's cosine similarity on explicit cpu, mps or cuda devices. It returns an N-by-M float32 similarity tensor on the selected device, validates finite nonzero real vectors and matching dimensions, and rejects unavailable accelerators. PyTorch is a base dependency. Floating-point scores can differ slightly from the previous implementation, so extractor version 26 requires a separate output path from earlier checkpoints.

`src/dataset/preprocessing/` implements non-embedding preprocessing as two independent utilities. FeaturePreprocessor.fit(records, settings) fits predictors; transform(records, sample_ids) returns X, sample IDs and column metadata. TargetPreprocessor.fit(targets) fits target scaling; transform(targets) returns y and inverse_transform(predictions) returns PLN. Both provide save(path=None)/load(path=None). FeaturePreprocessor.load also accepts an expected settings mapping to check selected field order. Neither class trains a regressor, creates splits or reads records automatically.

- `feature_preprocessor.py`: field validation/transformation, stable float64 X and column mappings, plus fit/transform/save/load in one class.
- `target_preprocessor.py`: independent robust scaling of finite nonnegative PLN amounts, including numeric strings, and inverse conversion without clipping.
- `transforms/`: fixed field rules, shared numeric validation and scikit-learn transformations.
- `io/`: model-input YAML validation, local record loading and atomic artifact storage.

load_records(directory, include_targets=True), implemented in src/dataset/preprocessing/io/records.py and exported from the package, reads record.json plus award.json and returns aligned records, sample_ids and unscaled targets for valid=true cases. Without targets it reads only predictors and IDs, requiring no award file. It never fits, splits or normalizes. A future training caller can load raw records, construct grouped splits and fit each preprocessor using only its training rows. A future prediction caller can load feature records and the saved feature preprocessor, then use the saved target preprocessor to return model outputs to PLN. This branch implements only reusable loading and preprocessing utilities; training/inference orchestration is not implemented. Original case files are never rewritten.

`configs/training/model_input.yaml` contains only feature_fields: an ordered, nonempty list of original predictor names, before encoding or scaling. It accepts cause, damage, limitations and the five supported tabular fields; duplicates, unknown fields, labels and extra configuration keys are rejected. Text selections are retained in the configuration but encoded separately through the existing embedding module, without normalization by this tool. The current preprocessor returns only the selected non-embedding blocks and requires at least one such field.

Preprocessing rules are fixed in transforms/rules.py, not configurable through YAML: judgment_year uses its final two digits divided by ten (2025 → [0.2, 0.5]), injured_party_count is unchanged, prior_payment uses log1p followed by training-fitted robust scaling, and instance/court_locality_size use one-hot vectors. Year encoding accepts integer years 2000–2099 only; other centuries, fractional years and missing years are rejected. Missing numeric predictors raise errors. None/not_available categories have a reserved missing column; unseen categories produce an all-zero field block. Missing selected keys are schema errors and unselected fields are ignored. Target amounts use fixed robust scaling without a logarithm: subtract the training median and divide by its interquartile range (with scikit-learn protection for zero range). For training amounts [100, 200, 300], y is [-1, 0, 1]; inverse transformation restores the amounts. The lower-level target helper also retains internal transformation support. Changing preprocessing rules requires a code change rather than a YAML option. These rules do not establish feature importance or empirically optimal preprocessing.

Related judgments must be split upstream before fitting, including inside every cross-validation fold. Held-out samples reuse unchanged imputation, category vocabularies and scaler statistics. fit does not create or verify splits. Prediction requires neither awards nor targets. Text embeddings remain in src.dataset.embeddings; aligning/concatenating those blocks with this tool's numeric columns is not implemented here. Missing text placeholders must not be embedded as facts.

FeaturePreprocessor.save()/load() default to checkpoints/preprocessing/feature_preprocessor.pkl; TargetPreprocessor.save()/load() default independently to checkpoints/preprocessing/target_preprocessor.pkl. Both paths are repository-relative and independent of the working directory. Directories are created on explicit save; no artifact is created during fit or record loading. Feature artifacts contain no target preprocessor, and target artifacts contain no predictor state. Either can be loaded without the other file. Version 4 artifacts retain their relevant fitted state, rules/schema and scikit-learn version; older layouts require regeneration. Pickle artifacts must be trusted. Text encoder identity and embedding dimensions belong to the later combined-pipeline artifact.

1. Create reproducible train, validation, and test splits before fitting preprocessing.
2. Encode each configured field appropriately: embeddings for free text, categorical encoders for categories, and scaled numeric values where needed.
3. Train a simple regression baseline first.
4. Select alternative classical or neural regression models through YAML configuration without changing pipeline code.
5. Compare MAE and RMSE and inspect errors by court, region, time range, and compensation band.

The third milestone is complete when a clean checkout can reproduce preprocessing, training, evaluation, and experiment metadata from configuration.

## Configuration layout

```text
configs/
  dataset/
    acquisition/
      api.yaml           # acquisition defaults overridden only by explicit CLI arguments
      features.yaml      # metadata/text selection, questions and required damage
      targets.yaml       # embedding settings, keyword groups and phrase patterns
      basal.yaml         # Basal model, device and extraction/review thresholds
  training/
    model_input.yaml     # ordered original model feature allowlist only
  train.yaml             # training controls, when training is implemented
  models/
    <model-name>.yaml    # model choice and parameters, when regression is implemented
```

The sole public target is total; it is fixed by the acquisition contract and is not a Basal setting. The extractor retains the internal field suma as its output adapter; historical notebook experiments retain their component schema. The sole regression label is the principal amount in the embedding-selected judgment sentence, aggregated across explicitly identified recipients when it is stated per person. Other sentences are not scanned or summed. Exclusion patterns aim to filter procedural costs, interest, rent and prior payments; role correctness depends on embedding selection and needs independent evaluation. `configs/training/model_input.yaml` selects original model input fields; acquisition still uses its separate features.yaml selection.

`configs/dataset/acquisition/targets.yaml` is active input to sentence selection. Keep one representative per distinct construction, without inflection/word-order/ending near-duplicates. Placeholder roles are rendered as Polish words and monetary values are neutralized only for embedding; raw text and numeric amounts retain exact source offsets. The pinned mean-pooled multilingual MiniLM encoder supports Polish, with explicit CPU/MPS/CUDA selection. Long sentences are embedded through all token windows rather than silently truncated. The matcher caches its model and pattern vectors across judgments. Candidate filtering is a cheap case-insensitive word-prefix/PLN check before embedding, with all required cues in the same fragment. Target candidates split at sentence boundaries and commas, except commas between digits; feature extraction retains full sentences. Comma splitting preserves source offsets and decimal amounts but can lose context or omit clauses whose role keyword occurs only before the comma. Only the selected fragment supplies the target; other fragments are not aggregated. This change advances extraction to version 26 and requires a fresh output path. No candidate means no embedding model loading; eligible sentences are encoded in batches. procedural_costs covers court, appeal, enforcement, witness and legal-representation expenses; its keyword group uses procedural context rather than the generic word koszt so clinical expenses remain eligible as damages. other_payments covers interest, periodic or capitalized rent and fines outside the selected one-off principal targets. Pattern constructions include joint liability and joint awards, supplementary claims, earlier advance payments, withdrawn or rejected claims and upheld judgments. The procedural spis stem makes cost-schedule sentences eligible for their exclusion group without admitting generic treatment costs. Currency recognition covers PLN, zł and grammatical forms of złoty and złotówka in both amount detection and text leakage filtering. Unrelated words sharing the zł prefix are rejected. Fully written-out amounts remain unsupported. Pattern or keyword changes invalidate checkpoint compatibility; use a different output path. Similar-looking payment sentences can still have different legal roles; independent quality checks remain necessary.

features.yaml contains metadata_fields and a nonempty text_fields mapping from field names to questions. At least one selected text field must have accepted source evidence; there is no per-field required list. Presence selects a field; there is no duplicate feature list or question mapping in basal.yaml or Python. Metadata names are validated against supported enrichments; text names must be English identifiers with nonempty questions. targets.yaml groups encoder settings and candidate_keywords under embedding and phrase groups under patterns. --config-dir selects a directory containing these four acquisition files and defaults to configs/dataset/acquisition. Reorganization preserves the normalized runtime configuration and version-21 checkpoint signature when values are unchanged. Default questions distinguish cause, harm and activities using general wording without examples or lists of harm types; this wording change requires a new output path for datasets using earlier questions. Question changes remain part of checkpoint compatibility and model decision cache identities. Confidence improvement has not been measured; source, relevance and leakage validation remain mandatory.

Expose only values deliberately selected between experiments. Keep technical source/leakage prompts, fixed implementation details and credentials out of experiment controls. Future data access, vectorization and training configuration should be added when implemented, without duplicating values across files. Secrets may be referenced by environment-variable name only.

## Initial technical decisions

- Runtime: Python 3.12 managed with `uv`; sync groups/extras first, then execute with `uv run --no-sync`. PyTorch and Transformers sentence encoding are base dependencies. Basal is optional through the extraction extra for CPU or the platform extras for macOS/Linux CUDA; the full get-data pipeline requires it. Reusable embeddings and CLI help do not require Basal.
- Program entry point: the installed get-data command calls src.dataset.get_data:main; run uv run --no-sync get-data --help after syncing the environment. Setuptools packages src.dataset and its subpackages for editable installation. Run acquisition from the repository checkout, which supplies configuration and output/cache paths. src/dataset/get_data.py handles CLI arguments only. src/dataset/acquisition/pipeline.py coordinates model lifecycle and extraction; acquisition/api.py validates SAOS responses and settings; acquisition/download.py handles resumable downloads; acquisition/checkpoints.py validates progress; storage/records.py enriches and exports records. Extraction and embedding code have separate packages. Within extraction/, basal_filtering.py coordinates the flow and features.py extracts and reviews predictors. The model/ package contains configuration, prompts and decision caching; source/ contains text normalization and passage batching; targets/ contains monetary evidence, principal resolution and prior-payment extraction; storage/files.py provides shared atomic writes and size limits. CLI flags, checkpoint compatibility and local record schemas are unchanged by this organization.
- Local experiments: notebooks/ contents are ignored; only .gitkeep is tracked. Notebook-specific tests skip when local inputs or their legacy configuration are absent.
- Current outputs: local per-judgment records and a resume checkpoint; diagnostic artifacts only in debug mode.
- Planned database: PostgreSQL with JSONB and pgvector.
- Configuration: YAML.
- Problem type: supervised regression.
- First model: a simple baseline chosen after the target distribution is inspected.
- Extraction prototype: pinned Basal model with PyTorch; MPS for local macOS work, CPU/CUDA when selected. Independent labeled evaluation is required before approving extracted training data.

## Main risks

- The judgment text may not identify a single unambiguous award.
- Direct targets inherit embedding role errors: an earlier cached CPU replay of 257931 selected a 3,000 PLN costs sentence at cosine 0.700052917. With the added cost-schedule construction and spis eligibility, that sentence is excluded at cosine 0.9543, but the case still has no judgment match. Separate awards in unselected sentences are not included.
- Search terminology may miss relevant judgments or include unrelated uses of compensation terms.
- Reasoning text can reveal the target directly or indirectly.
- Inflation and changes in judicial practice can create temporal drift.
- Related cases can leak across random row-level splits.
- Sparse regions or courts can make subgroup metrics unstable.
